# گرفتن سیگنال طلای ۱۸ عیار از موبایل (Claude Code)

روش «بدون زیرساخت»: از اپ موبایلِ Claude Code یک سشن روی این ریپو باز می‌کنی،
فایل CSV تایم‌فریم M5 را ضمیمه می‌کنی و یک پیام کوتاه می‌فرستی. سیگنال فارسی برمی‌گردد.

## هر بار فقط این کار را بکن
۱. در اپ موبایل، یک سشن Claude Code روی ریپو `gold18` باز کن.
۲. فایل CSV را ضمیمه کن (📎).
۳. این پیام آماده را بفرست:

```
فایل CSV پیوست را با bot/signal_engine.py اجرا کن و فقط خروجی سیگنال فارسی را بده.
```

همین. خروجی شامل خلاصه بازار + سیگنال‌ها (یا پیام «شرایط مناسب نیست») است.

## اجرای مستقیم (اگر خودت ترمینال داشتی)
```
python3 bot/signal_engine.py /path/to/Gold18_m5.csv
```

## مدل هزینه (طلاین / Taline)
«کارمزد ۵۰۰۰ تومان ثابت» تبلیغاتی است؛ هزینه‌ی واقعی **اسپرد** است:
حدود **۰٫۴٪ هر طرف = ۰٫۸٪ رفت‌وبرگشت**. کارمزد ثابت فقط روی معاملات خیلی کوچک مهم می‌شود.
هزینه‌ی کل رفت‌وبرگشت = `۲×اسپرد + ۲×کارمزد‌ثابت/حجم + لغزش` ≈ **۰٫۸۵٪** با پیش‌فرض‌ها.

## تنظیمات (اختیاری، از طریق متغیر محیطی)
| متغیر | پیش‌فرض | توضیح |
|-------|---------|-------|
| `SPREAD_PER_SIDE_PCT` | `0.4` | اسپرد هر طرف (از تحقیق طلاین) |
| `FLAT_FEE_TOMAN` | `5000` | کارمزد ثابت هر معامله |
| `NOTIONAL_TOMAN` | `20000000` | حجم معمول هر سفارش تو — **این را با عدد واقعی تنظیم کن** |
| `SLIPPAGE_PCT` | `0.0` | بافر لغزش اضافی |
| `MIN_TP_ATR_SWING` | `1.0` | حداقل هدف سویینگ (× ATR) |
| `MIN_TP_ATR_SCALP` | `1.5` | حداقل هدف اسکالپ (× ATR) |
| `MIN_NET_RR` | `1.5` | حداقل نسبت ریسک‌به‌ریوارد خالص |
| `MIN_NET_PROFIT_PCT` | `0.5` | حداقل سود خالص هدف اول بعد از هزینه |
| `MAX_SIGNALS` | `3` | سقف تعداد سیگنال |

مثال (سفارش کوچک ۲ میلیونی که کارمزد ثابت مهم می‌شود):
`NOTIONAL_TOMAN=2000000 python3 bot/signal_engine.py file.csv`

## جبران هزینه در سطوح سیگنال
هر سیگنال حالا این‌ها را نشان می‌دهد تا هزینه شفاف و لحاظ‌شده باشد:
- **قیمت خرید/فروش واقعی (با اسپرد):** قیمتی که واقعاً معامله می‌کنی (نه قیمت مرجع).
- **قیمت سربه‌سر:** قیمتی که تا آن‌جا سود خالصت صفر است؛ سود واقعی از بعد از آن شروع می‌شود.
- **حد سود:** طوری انتخاب می‌شود که سود خالص بعد از هزینه **≥ ۱٪** باشد (`MIN_NET_PROFIT_PCT`).

⚠️ مهم: جابه‌جایی سطوح هزینه را حذف نمی‌کند — فقط دقیق و قابل‌اقدام می‌کند. حد ضرر برای
«جبران» دورتر نمی‌رود (این فقط ریسک را زیاد می‌کند).

### ورود لیمیت (پول‌بک) برای جبران هزینه
اگر روند درست باشد ولی قیمت فعلی خیلی به هدف نزدیک باشد (بعد از هزینه سودی نماند)،
به‌جای «بدون معامله»، سیگنال یک **ورود لیمیت شرطی** می‌دهد:
- **خرید:** منتظر پول‌بک به نزدیک‌ترین **حمایت واقعی** (تا حداکثر ۳٪ سویینگ / ۱٫۵٪ اسکالپ).
- **فروش:** منتظر پول‌بک به نزدیک‌ترین **مقاومت واقعی**.
- از آن نقطه‌ی بهتر، فاصله تا هدف بیشتر می‌شود و هزینه جبران می‌شود.
- ⚠️ ورود لیمیت فقط اگر قیمت به آن نقطه برگردد اجرا می‌شود (ممکن است پر نشود).
- اگر ورود فوری هم معتبر باشد، هر دو نشان داده می‌شوند.

## نکات مهم
- موتور کاملاً **قطعی** است (بدون مدل زبانی): هر بار روی داده‌ی یکسان، خروجی یکسان.
- منطق دقیقاً از `signal_prompt.md` پیروی می‌کند: امتیازدهی متقارن روند، گیت
  هزینه، رفع look-ahead (امتیاز روی کندل بسته‌شده)، و حالت‌های SWING/SCALP.
- **هوک راه‌اندازی:** فایل `.claude/hooks/session-start.sh` در هر سشن جدیدِ وب/موبایل
  pandas را نصب می‌کند. برای اینکه روی همه‌ی سشن‌های آینده اعمال شود، این تغییرات
  باید در برنچ پیش‌فرض ریپو merge شوند.
- ⚠️ با هزینه‌ی واقعی طلاین (~۰٫۸۵٪ رفت‌وبرگشت)، **اسکالپ عملاً سودده نیست**؛ تمرکز روی
  سویینگ با هدف‌های بزرگ (~۳٫۵٪+) باشد.
- ⚠️ برگشت معامله: اگر قیمت طلاین >۵٪ با بازار فرق کند، پلتفرم حق ابطال معامله را دارد.
- ⚠️ حجم سفارش را بزرگ نگه دار تا کارمزد ثابت ۵۰۰۰ تومانی ناچیز بماند (`NOTIONAL_TOMAN`).
